# CUDAynamics System Editor

При запуске открывается главное меню **CUDAynamics System Editor**. Из него можно перейти в мастер создания системы или в менеджер удаления существующих систем. В нижнем правом углу меню выбирается язык интерфейса: English используется по умолчанию, также доступен Русский. Выбранный язык передаётся во все открываемые окна; из мастера создания и менеджера удаления можно вернуться в главное меню.

Менеджер удаления читает библиотеку из выбранной папки `cudaynamics-master`, показывает ID и `Name:` каждой системы и удаляет только явно отмеченные строки после подтверждения. Вместе с папкой системы очищаются `systemsHeaders.h`, `main.cpp`, `CUDAynamics.vcxproj` и `CUDAynamics.vcxproj.filters`. Перед изменениями папки удаляемых систем и регистрационные файлы перемещаются в восстанавливаемую копию внутри `.cudynamics-editor-backups`.

Кнопка **Edit System / Редактировать систему** открывает двухшаговый редактор существующей библиотеки. На первом шаге выбираются проект и система, после чего можно изменить ID системы, `Name:`, имена переменных и имена пользовательских параметров. Формулы и структура численных методов не редактируются: идентификаторы заменяются одновременно в enum и обращениях `V`, `Vnext`, `P`, а внутренние локальные переменные кода остаются нетронутыми. Служебные параметры `method`, `COUNT`, `signal`, `symmetry` не предлагаются для переименования. На втором шаге выбирается метод запуска по умолчанию (только из методов, уже перечисленных в `enum method`) и редактируются строки `var` и `param` конфигурационного `.txt`: режим `Fixed/Linear/Step/Random/Normal`, минимум, максимум, шаг, количество, среднее и отклонение. Если старая система не содержит `enum method`, поле метода недоступно, но остальные данные можно редактировать. При смене ID обновляются папка, имена `.cu/.h/.txt`, сохранённый исходник и четыре регистрационных файла проекта. Перед применением создаётся резервная копия в `.cudynamics-editor-backups`.

Настольный мастер добавления пользовательских динамических систем в CUDAynamics.

## Возможности

- основной сценарий — изображение формул (`PNG`, `JPG`, `WebP`, `BMP`);
- локальный OCR через `pix2tex` или облачное распознавание изображения через OpenAI;
- ручной текстовый ввод и обязательная визуальная проверка распознанных уравнений;
- раздельная классификация переменных состояния, алгебраических переменных и входного сигнала;
- автоматическое выделение параметров и добавление `dt/dt = 1`, если в формулах используется независимое время `t`;
- автоматическое распознавание записи `F(t)` как входного сигнала и генерация отдельных ветвей прямоугольной, синусоидальной и треугольной формы;
- редактируемые условные события в конце шага или после выбранного уравнения;
- выбор метода интегрирования по умолчанию из отмеченных для генерации методов;
- выбор схем: явный/полуявный/неявный Эйлер, явная/неявная средняя точка, RK4, фиксированный DP8, VSCD;
- настройка шага, времени моделирования, времени переходного процесса, начальных значений и параметров;
- для каждой переменной и параметра — режим `Fixed` или `Count`, минимум/начальное значение, максимум и число равномерно варьируемых значений;
- генерация совместимых `.h`, `.cu`, `.txt`;
- генерация `.cu` по нативному шаблону существующих систем: прямые `V(...)`, `Vnext(...)`, `P(...)` и скалярные стадии без универсального массива правых частей;
- предпросмотр полного diff до записи;
- регистрация системы в `systemsHeaders.h`, `main.cpp`, `.vcxproj` и `.vcxproj.filters`;
- резервная копия изменяемых файлов и откат при ошибке записи.

## Установка и запуск

```powershell
cd "Cudaynamics Project Folder\cudaynamics-system-builder"
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Или запустите `run.bat`: если рядом существует `.venv`, он автоматически использует именно это окружение. Локальный OCR `pix2tex` уже включён в `requirements.txt`.

В качестве альтернативы выберите backend `openai` и введите API key. Ключ используется только для текущего запроса, не сохраняется на диск. Изображение передаётся модели как base64 data URL через Responses API; запрос создаётся с `store: false`.

## Поддерживаемый ввод

По одному уравнению в строке:

```text
dx/dt = sigma*(y-x)
dy/dt = x*(rho-z)-y
dz/dt = x*y-beta*z
q = x+y
```

Поддерживаются также `x'`, `dot(x)`, `\dot{x}` и `\frac{dx}{dt}`. Стандартный вывод pix2tex с `\left\{`, окружениями `array`, `cases`, `aligned`, спецификатором `{l}`, строками `\\` и лишними группами `{{...}}` нормализуется автоматически. Строка `q = ...` считается алгебраической: `q` записывается в траекторию CUDAynamics, но не интегрируется. Тип любой строки можно поменять в таблице проверки.

Неизвестная функция только от времени, например `F(t)` или `I(t)`, автоматически становится входным сигналом. То же самое можно сделать вручную, выбрав для строки тип «Входной сигнал». Для сигнала мастер добавляет `dt/dt = 1`, параметры `Idc`, `Iamp`, `Ifreq`, `Idel`, `Idf` и выбор `square/sine/triangle`. Поддерживается один входной сигнал на систему — это соответствует формату существующих систем CUDAynamics.

Условный скачок добавляется отдельной строкой в блоке «Условные изменения». Для него можно выбрать позицию после конкретного уравнения или конец шага. Правые части присваиваний сначала вычисляются во временные значения, поэтому изменения семантически одновременны, а не зависят от порядка записи. Существующие алгебраические переменные разрешено проверять и изменять. Неизвестное имя слева от присваивания автоматически создаётся как внутренняя переменная условия: она не интегрируется и сохраняет значение между шагами до следующего срабатывания условия. Такая переменная не показывается как отдельное уравнение и не предлагается в списке типов, но появляется на экране значений по умолчанию с ролью «задаётся условием». Прочие неизвестные имена в условии и правых частях становятся параметрами.

Пользователь вводит физическое время моделирования и переходного процесса. Мастер делит его на `h` и записывает в описание целое число шагов. Если время не делится на шаг точно, число округляется вверх, чтобы расчёт не оказался короче заданного интервала; итоговое количество шагов сразу показано под полями.

Если пользователь выбрал или перетащил исходное изображение, при добавлении системы оно копируется в `systems/<id>/` рядом с файлами `.cu`, `.h` и `.txt`. Имя файла совпадает с ID системы, а исходное расширение сохраняется: например, `lorenztest.png`. PDF также можно выбрать или перетащить для сохранения как исходного документа; текущий OCR работает с растровыми изображениями, поэтому страницу PDF для распознавания нужно предварительно экспортировать в PNG, JPG или WebP.

Перед генерацией мастер отдельно проверяет ID по существующим папкам `systems`, а отображаемое название — по строкам `Name:` существующих описаний. Сравнение выполняется без учёта регистра. При совпадении добавляется первый свободный числовой суффикс (`id2`, `id3`, …; для отображаемого названия — `Name 2`, `Name 3`, …), поля интерфейса обновляются, а пользователь получает предупреждение с исходными и новыми значениями.

## Зарезервированные имена

Имена `h`, `H`, `method`, `COUNT`, `symmetry`, `signal`, `name`, `numb`, названия численных методов и форм сигналов заняты генерируемым CUDA-кодом, препроцессором или `.txt`-описанием. Также проверяются объектные макросы CUDAynamics, способные испортить enum ещё до компиляции. При их использовании мастер не отбрасывает систему, а символически переименовывает пользовательский идентификатор: например, `h` становится `h_custom`. Если такое имя уже существует, используется `h_custom2` и далее. Замена выполняется в левых и правых частях уравнений, вложенных алгебраических выражениях, условиях и присваиваниях событий. UI показывает предупреждение и итоговую таблицу переименований.

Имя `t` имеет особое правило. Обычное `dt/dt = 1` считается штатным временем и сохраняется. Если при наличии входного сигнала пользователь задаёт другое уравнение для `t`, оно переименовывается в `t_custom`, а для формы сигнала отдельно добавляется внутреннее `dt/dt = 1`. Параметры сигнала `Idc`, `Iamp`, `Ifreq`, `Idel`, `Idf` сохраняют стандартные имена; одноимённые пользовательские переменные переименовываются.

Основные поддерживаемые функции: `sin`, `cos`, `tan`, `sec`, `csc`, `cot`, обратные и гиперболические тригонометрические функции, `abs`, `sign`, `min`, `max`, `sqrt`, `pow`, `exp`, `log`, `log2`, `log10`, `floor`, `ceil`, `mod`, `erf`, `erfc`, `atan2` и `hypot`. Можно использовать как обычную запись `sin(x)`, так и соответствующую LaTeX-запись `\sin(x)`.

## Важные численные детали

- Явный Эйлер, полуявный Эйлер, явная средняя точка и RK4 разворачиваются непосредственно в `finiteDifferenceScheme_`, как в ручных файлах `systems`. Вызова универсальной функции правых частей и массива `derivative[]` нет. Массивы используются только алгоритмами, которым они действительно нужны: таблицей стадий DP8 и решением линейной системы Ньютона.
- Алгебраические переменные пересчитываются на каждой промежуточной стадии метода, а после шага — ещё раз для итогового состояния.
- Алгебраические зависимости должны быть ациклическими. Мастер определяет безопасный порядок вычисления, рекурсивно раскрывает вложенные алгебраические выражения для Якобиана, VSCD и полуявной схемы и сообщает о цикле.
- Сигнал не интегрируется: его значение вычисляется от стадийного времени. Поэтому RK4/DP8 используют соответствующее время каждой стадии, а не одно значение на весь шаг.
- Для неявного Эйлера и неявной средней точки генератор заранее дифференцирует правые части по переменным состояния. В CUDA-код попадает аналитический Якобиан (с раскрытыми алгебраическими зависимостями), а не конечные разности. Метод Ньютона выполняет не более восьми итераций. После добавления систему нужно проверить на характерных шагах `h`, `h/2`, `h/4`.
- `ExplicitDormandPrince8` соответствует принятому в существующих системах CUDAynamics фиксированному 13-стадийному шагу; адаптивного выбора шага нет.
- Универсальный `VariableSymmetryCD` выполняет прямой последовательный и обратный неявный проход. Результат зависит от порядка состояний в таблице. Если обратное скалярное уравнение линейно по текущей координате, генератор заранее выражает его точное решение. Для нелинейного уравнения создаётся скалярный метод Ньютона с заранее вычисленной аналитической производной.
- Условные события применяются в выбранной пользователем позиции каждого метода. Автоматическое извлечение reset-строки из изображения пока не выполняется: условие и присваивания нужно добавить в UI после распознавания системы.
- Стохастические слагаемые и метод Maruyama не генерируются.

## Что изменяется в основном проекте

Только после подтверждения на последнем экране:

1. создаётся `systems/<system_id>/<system_id>.h`;
2. создаётся `systems/<system_id>/<system_id>.cu`;
3. создаётся `systems/<system_id>/<system_id>.txt`;
4. добавляется include в `systemsHeaders.h`;
5. добавляется `addKernel(...)` в `main.cpp`;
6. `.cu` добавляется в `CUDAynamics.vcxproj` и `.vcxproj.filters`.

До записи показывается unified diff. Исходные четыре файла сохраняются в
`.cudynamics-builder-backups/<дата-время>/`. Повторное использование существующего ID блокируется.
